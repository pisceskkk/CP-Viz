PCP 与 DCP：算力切分 vs 显存切分

PCP 切分输入序列算力，DCP 复用现有进程组切分 Attention KV Cache 显存

PCP (Prefill Context Parallel) 切算力 · 降 TTFT

按 DualChunkSwap 头尾对称切分长 Prefill 输入序列，扩展 World Size 为 PCP × TP。

DCP (Decode Context Parallel) 切显存 · 降 TPOT

复用 PCP / TP 进程组，默认将所有 Attention KV Cache（含主 KV 与 Indexer）交错分片（1/DCP）。

DCP ①：Virtual Block 与交错 Slot Mapping

默认切分所有 Attention KV Cache：通过 Virtual Block 跨卡交错落盘，非归属 Rank 写 -1

交错映射公式（block_size % I == 0）

VBlock = block_size × DCP  |  target_rank = ((pos % VBlock) // I) % DCP

Attention KV 默认全切分 (AttentionSpec.dcp_sharded = True)

Full Attention、主 KV 及 Indexer 默认均按 DCP 切分；非序列状态按 Group 设为 False。

DCP ②：Decode 局部注意力与 dcp_a2a_fused

收集完整 Query Heads → 对本地 1/DCP KV 分片算局部 Attention → All2All LSE 加权归并

1. Query Gather / Replicate

跨 DCP 收集完整 Q Heads（DCP==PCP 时免通信）。

2. 无损 LSE 打包 All2All

Triton 打包 BF16 O_j 与 FP32 LSE_j 单次 All2All。

3. LSE 稳定加权归并

w_j = exp(L_j - max L)  |  O = Σ(w_j·O_j) / Σw_j

DCP ③：Chunked Prefill（AllGather KV Cache 方案）

分块 AllGather 历史 Cached KV 还原连续序列，迭代计算 Context Attention 并与 Current Attention 做 LSE 修正合并

分块 Workspace 迭代 AllGather 历史 KV

按 lcm(block_size, I × DCP) 划窗收集历史 KV 并通过 kv_rank_offsets 还原连续顺序，控制单步通信峰值显存。

correct_attn 增量 LSE 合并

每次迭代算出的 (O_chunk, lse_chunk) 与前序结果及当前步 (O_cur, lse_cur) 按 LSE 权重精确归并。

DCP ④：Sparse Attention 的 Sharded Indexer 数据流

Indexer Cache 与主 KV 按相同 DCP Token Owner 切分：各卡选本地候选 Top-K → AllGather 归并全局 Top-K → Remap 本地稀疏注意力

1. 本地候选 Top-K 选择

LightningIndexer 对本卡 1/DCP 索引缓存选出 [X, topk]。

2. 跨卡归并全局 Top-K

打包 (indices, score) 跨 DCP AllGather 后归并出全局 [X, topk]。

3. Remap 本地 Select & All2All

过滤出落在本卡的 local_topk 读取主 KV，算完经 All2All 归并。

PCP ①：MRV2 单步 Batch 生命周期

Scheduler 维持全局 Batch，Worker 侧通过 PCPManager + AscendPCPManager 切分与还原

PCP ②：DualChunkSwap 头尾对称切分

切分为 2P 个 Chunk，Rank r 取 (r, 2P-1-r) 展开为 2 条独立虚拟请求段

2x 独立虚拟请求段 (RankSegment)

Head 与 Tail 作为两条独立虚拟请求行，各自携带真实 positions 与 num_computed_tokens。

短请求自动复制 (replicated_requests)

PCP+DCP 下若请求不够分满 2P 个 Chunk，自动全卡复制以保证集合通信步调一致。

PCP ③：Prefill 与 Chunked Prefill 算子级数据流

计算本地 [X/CP, hs] Query 的同时，主 KV 与 Indexer KV 跨 CP AllGather 写入完整 [CTX, hs_c] Cache，并衔接 o_proj 与 SP/MoE

1. 主 KV 与 Indexer 跨 CP 同步

kv_down_proj 与 Wk 经 AllGather CP 汇聚后写入 [CTX, hs_c]。

2. 本地 1/CP Query 稀疏注意力

LightningIndexer 选出 [X/CP, 2048]，从完整 KV select 计算注意力。

3. o_proj 两种模式与 SP 衔接

支持 AG weights (TP=1) 或 Slice heads + RS(SP) 衔接 LayerNorm / MoE。

PCP ④：Decode 请求的两种调度模式

根据 KV Cache 与状态是否跨卡分片，在 PCPManager._iter_rank_chunks 中自动选择轮询分片或全卡复制

MODE A · DECODE REQUEST SHARDING

按请求轮询分片（PCP > 1, DCP = 1）

当历史 KV Cache 在各 PCP Rank 上完整持有（DCP = 1）且模型无跨 PCP 切分状态时开启：

  • 分配规则：按 owner_rank = decode_ordinal % PCP 将不同 Decode 请求轮询分配到各 PCP Rank。
  • MTP 约束：同一 Decode 请求的 K + 1 个验证 Token 始终绑定在同一 Owner Rank。
  • KV 同步：各卡仅计算 1 / PCP 的 Decode 请求，每层产生的新 Token KV 跨 PCP AllGather 落盘。
MODE B · REPLICATED DECODE

全 Rank 复制调度（DCP > 1 或含跨卡状态）

当叠加 DCP > 1（历史 KV 跨卡分片）或包含跨 TP × PCP 切分的线性状态层时启用：

  • 分配规则：所有 PCP Rank 接收相同的 Decode Query 序列（replicated = True）。
  • 注意力协同：各 Rank 拿相同的 Decode Query 读取本卡持有的 1 / DCP 历史 KV 分片，经 dcp_a2a_fused 归并。
  • 状态层推进：各 Rank 并行推进本卡负责的 1 / (TP × PCP) Recurrent State 分片。
维度 Mode A：Decode Request Sharding Mode B：Replicated Decode
启用条件 PCP > 1, DCP = 1 且无跨 PCP 状态层 DCP > 1 或含跨 TP × PCP 状态层
单卡 Decode 算力 分摊为 1 / PCP 请求数 各卡处理全量 Decode Token（KV 读取降为 1 / DCP）
层内通信开销 每层 AllGather 新产生的 Decode KV 并写 Cache 走标准 DCP 路径（AllGather Q + dcp_a2a_fused）

PCP ⑤：显存挑战与 TP × PCP 权重切分

纯 PCP 下单卡默认复制权重与完整 KV Cache；通过跨 TP × PCP 联合切分常驻权重释放单卡 HBM

01 · EMBEDDING & LM HEAD

词表权重跨 TP × PCP 切分

enable_pcp_embedding_lmhead_weight_sharding = True（默认开启）：大词表 Embedding 与 LM Head 权重按 TP × PCP 联合切分，适用于所有 Attention 后端。

02 · ATTENTION O_PROJ

o_proj 跨 PCP 权重/激活切分

enable_pcp_o_proj_weight_sharding = True（SFA/DSA 默认开启）：支持 TP=1 下临时 AllGather weights，或按 Head 切分后走 ReduceScatter (SP)。

03 · LINEAR ATTENTION & STATE

线性层权重与状态扩维切分

通过 PCPColumnParallelLinear 与 PCPRowParallelLinear，将线性注意力（如 KDA）的投影权重与常驻 SSM 状态按 TP × PCP 切分。

PCP + DCP 叠加：算力与显存双重切分

在 TP × PCP 网格上复用进程组建 DCP（DCP = PCP 或 DCP = TP × PCP），同时切分 Prefill 算力与 KV Cache 显存

01 · TOPOLOGY & KV OWNERSHIP

1. 通信拓扑与 KV 落盘规则

  • PCP-first 转置建组：逻辑 DCP 按 flat_idx = tp_rank * PCP + pcp_rank 组建（先跨 PCP，再跨 TP）。
  • HCCL 排序映射：通过 dcp_collective_rank_order 对齐物理 ProcessGroup 顺序。
  • 单次掩码落盘：仅满足 (pos // I) % DCP == dcp_rank 的 Token 写物理 Slot，其余置 -1。
02 · STACKED PREFILL

2. Stacked Prefill 协同

  • 当前步新 KV：build_pcp_ordered_slot_mapping 按 padded_gather_idx 重排全局 Slot 并过滤 Padding。
  • 历史 Cached KV：基于 global_batch 生成统一的跨 DCP AllGather 发送上界，接收后按本地 Segment 区间消费。
  • 本地 Query 计算：各卡仅计算 1 / PCP 本地 Query Token。

GLM-5.3-Flash 混合架构与 CP 职责拆解

34 LAYERS · KDA

KDA 线性注意力

64 Heads 与 SSM 状态按 TP×PCP 切分；Prefill 先 AllGather 还原因果顺序，输出经 ReduceScatter 切回本地。

11 LAYERS · KPOOL

KPool 4:1 索引器

NoPE SFA 主注意力

部署场景选型与未来演进规划

Prefill / Decode 阶段的 CP 选型策略与 vLLM-Ascend 下一步重点演进方向

01 · PREFILL SCENARIO

Prefill 阶段选型策略

  • 常规长序列（优化 TTFT）：稀疏注意力模型通常开启 PCP（DualChunkSwap 头尾对称切分），切分 Prefill 计算序列以压降首字时延 TTFT。
  • 超长序列或 KV Cache 容量受限：在开启 PCP 的基础上同步开启 DCP（PCP + DCP），跨卡交错切分主 KV Cache 释放显存容量。
02 · DECODE SCENARIO

Decode 阶段选型策略

  • 中短序列场景：优先采用标准 DP / TP 部署，无需开启 CP，避免额外跨卡集合通信开销。
  • 长序列场景（优化容量与 TPOT）：使用 TP + DCP 交错切分历史 KV Cache 释放显存容量，同时将单卡每步 KV HBM 访存带宽降至 1 / DCP 以优化 TPOT。

未来演进规划（Roadmap）

NEXT STEPS

1. Indexer 切分泛化（K3.1 Pro → GLM-5.3）

将 Sharded Indexer（跨 DCP 切分 Indexer Cache + distributed_topk 候选归并）从 K3.1 Pro 的 LightningIndexer 泛化适配至 GLM-5.3（KPool Indexer），消除长序列下 Indexer Cache 的全卡复制开销。

2. 动态 CP（Dynamic Context Parallel）

支持根据请求的实际序列长度与系统 KV 负载动态调整 CP 并行度与执行路径：中短序列走无 CP / 低并行度路径免除通信开销，长序列按需动态启用 PCP / DCP。

    def _dcp_all_gather_fragments(self, *tensors: torch.Tensor, dim: int) -> tuple[torch.Tensor, ...]:
        if not tensors:
            return ()
        split_sizes = [tensor.shape[-1] for tensor in tensors]
        pcp_group = getattr(self, "pcp_group", None)
        if dim == 1 and pcp_group is not None and pcp_group.world_size > 1:
            # Query heads are replicated across PCP ranks. Gather only
            # distinct TP heads when DCP spans the full TP x PCP domain.
            if self.dcp_size == pcp_group.world_size:
                return tensors
            gathered = self.tp_group.all_gather(torch.cat(tensors, dim=-1).contiguous(), dim=dim)
        else:
            gathered = self._dcp_all_gather(torch.cat(tensors, dim=-1), dim)
        return torch.split(gathered, split_sizes, dim=-1)

    def _merge_dcp_attention_output(self, attn_output, softmax_lse, *, defer_combine=False):
        pcp_group = getattr(self, "pcp_group", None)
        if pcp_group is not None and pcp_group.world_size > 1:
            tp_size = self.tp_group.world_size if self.dcp_size > pcp_group.world_size else 1
            return torch.ops.vllm.dcp_a2a_fused(
                attn_output, softmax_lse, tp_size, 1,
                self.tp_group.unique_name, pcp_group.unique_name,

def distributed_topk(indices, scores, group, topk: int, interleave: int, *, return_local: bool = False):
    from vllm_ascend.ops.triton.sharded_indexer import MAX_FUSED_TOPK, merge_packed_candidates, pack_local_candidates
    rows, local_k = indices.shape[0], indices.shape[-1]
    output = torch.empty((rows, 1, topk), dtype=torch.int32, device=indices.device)
    presorted = topk == MAX_FUSED_TOPK and local_k <= MAX_FUSED_TOPK
    query_tile = gathered_candidate_row_tile(rows, group.world_size, local_k)
    for start in range(0, rows, query_tile):
        end = min(start + query_tile, rows)
        packed = pack_local_candidates(
            indices[start:end], scores[start:end], group.world_size, group.rank_in_group,
            interleave, sort_candidates=presorted, fuse_sort=return_local and presorted,
        )
        gathered = group.all_gather(packed, dim=0)
        merge_packed_candidates(
            gathered, packed.shape[0], group.world_size, topk,
            local_rank=group.rank_in_group if return_local else None,
            interleave=interleave, out=output[start:end],
            presorted=presorted, owner_sharded=return_local and presorted,
        )
    return output

    def replicated_requests(
        self, num_scheduled_tokens: np.ndarray, is_prefilling: np.ndarray
    ) -> np.ndarray:
        """Per global request, whether every PCP rank gets the whole query."""
        num_chunks = 2 * self.pcp_world_size
        query_lens = np.asarray(num_scheduled_tokens, dtype=np.int64)
        replicated = ~np.asarray(is_prefilling, dtype=np.bool_)
        if self.dcp_world_size > 1:
            chunk_sizes = (query_lens + num_chunks - 1) // num_chunks
            drops_a_chunk = (num_chunks - 1) * chunk_sizes >= query_lens
            replicated |= drops_a_chunk
        return replicated

    def _iter_rank_chunks(self, rank: int, num_scheduled_tokens: np.ndarray, is_prefilling: np.ndarray):

            elif self.shard_decode_requests:
