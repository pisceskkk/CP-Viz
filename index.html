CP 特性总览：以 GLM-5.3-Flash 为锚点的算力与显存切分

45 层混合主干（mHC + 34 层 KDA 线性注意力 + 11 层 NoPE SFA / KPool 稀疏注意力 + 288 MoE）在 PCP & DCP 下的协同全景

PCP (Prefill Context Parallel) 算力切分 · 降低 TTFT

将长 Prefill 按 DualChunkSwap 切为 2x 虚拟请求段：KDA 按 TP×PCP 切 Head 并还原因果顺序，SFA+KPool 异步 Gather Key 并仅对本地 1/PCP Query 算稀疏注意力。

DCP (Decode Context Parallel) 显存切分 · 提升容量与 TPOT

复用 PCP / TP 进程组：KPool Indexer (4:1) 全量复制零通信直出 Top-2051，而占显存大头的 SFA 512维主 KV 按虚拟块跨卡交错分片（1/DCP），Decode 经 dcp_a2a_fused 归并。

DCP 核心机制 ①：GLM-5.3-Flash 虚拟块与异构 Cache 交错落盘

通过 dcp_sharded: list[bool] 区分 5 个 Cache Group：仅 Group 0 SFA 主 KV 按 DCP 交错切分，非归属 Rank 写 PAD_SLOT_ID (-1)

交错映射公式（SFA+DCP: I == block_size == 128）

virtual_block_size = 128 × DCP   |   vblock_offset = pos % virtual_block_size
target_dcp_rank = (vblock_offset // 128) % DCP  （非 Owner 写入 -1 跳过落盘）

GLM-5.3-Flash 的 dcp_sharded 异构分片契约

• Group 0 (SFA 512维主 KV)：dcp_sharded=True，单卡显存降至 1/DCP。
• Group 0/1 (KPool 4:1 + Tail) & Group 2~4 (KDA SSM)：dcp_sharded=False。

DCP 核心机制 ②：GLM-5.3-Flash Decode 局部稀疏注意力与 dcp_a2a_fused

Decode 绝不跨卡搬运 KV Cache：sparse_index_remap 映射本地 Top-K → 本地 1/DCP KV 计算 → Triton 打包 (O_j, FP32 LSE_j) 归并

GLM-5.3-Flash 动态算子流 · DCP Decode (MTP=5) 从 KPool 全局 Top-2051 到 sparse_index_remap 与 dcp_a2a_fused

1. sparse_index_remap 过滤

Replicated KPool 选出全局 Top-2051 后，Triton Kernel 将其过滤并重映射为属于本 DCP Rank 的物理 KV Slot 及可见长度。

2. 无损 LSE 打包 All-to-All

Triton 将局部 O_j [6B, 64, 512] 与 FP32 LSE_j（INT32 位保留或 Base-256 编码）打包为单次 all_to_all_single。

3. 数值稳定 LSE 加权归并

m = max_j(L_j),   w_j = exp(L_j - m)
O = Σ(w_j · O_j) / Σ w_j

DCP 核心机制 ③：GLM-5.3-Flash Chunked Prefill 与 Indexer 双模式

GQA DCP 已移除（RFC #21305）；GLM-5.3-Flash 默认采用 Replicated KPool (4:1) + Compact KV Block Gather

GLM-5.3-Flash 动态算子流 · Replicated KPool (默认) vs Sharded Indexer (Radix Sort) + _record_dcp_kv_gather_context

模式 A：Replicated KPool Indexer（GLM-5.3-Flash 默认）

KPool 4:1 池化后每 Token 仅占 32 Elements（主 KV 的 ~1/16），全卡复制开销极小，直接零通信选出一致的全局 Top-2051！

Prefill/Mixed 紧凑 KV 收集 & 模式 B（Sharded Indexer）

Prefill 写完新 KV 后仅对本步活跃块 ID (kv_gather_block_ids) 跨 DCP AllGather；可选 Sharded Indexer 支持 Triton Radix Sort 跨卡归并。

DCP 核心机制 ④：History / Current 拆分与通信计算重叠

在 MTP 投机验证等多 Token 因果 Decode 场景下，将 DCP 分片的历史 KV 与本地当前步 KV 拆流并行

flowchart LR Q["Query Heads Gather"] --> H_ATTN["主流：History FIA
(对本地 1/DCP 历史 KV)"] H_ATTN --> COMM["通信流：dcp_a2a_fused
(defer_combine=True 异步 All2All)"] H_ATTN --> C_ATTN["主流：Current FIA
(对当前步新 Token 完整 KV)"] COMM --> MERGE["主流：fused_dcp_lse_combine
(一次性合并所有 History Ranks + Local Current)"] C_ATTN --> MERGE

为什么必须拆分？

MTP 验证时单请求携带 K+1 个因果 Query Token：历史 KV 已按 DCP 分散在各卡，而当前步新 Token KV 尚未跨卡切分。

双流重叠隐藏 All2All

在独立通信流 cp_decode_comm_stream 上执行历史输出的 Pack 与 All-to-All，与主流上的 Current Token FIA 完全并行。

单次归一化避免重复计数

fused_dcp_lse_combine 将接收缓冲区与 local_output / local_lse 一并归约，保证 Current KV 精确计数一次。

PCP 核心机制 ②：DualChunkSwap 切分与 GLM-5.3-Flash 双向映射契约

将长度为 L 的请求拆为 2P 个 Chunk，Rank r 展开为 Head(r) 与 Tail(2P-1-r) 两条独立虚拟请求段（RankSegment）

GLM-5.3-Flash 动态算子流 · 从 2x 虚拟请求展开到双向映射表（padded_gather_idx ⇄ hidden_restore_idx）如何驱动 KDA 与 SFA

MRV2 核心演进：2x 独立虚拟请求行（RankSegment）

Head 与 Tail 直接展开为 2 条独立虚拟请求行（Buffer 容量 2 * max_num_reqs），各自携带真实 positions 与 num_computed_tokens。

短请求自动复制保护（replicated_requests）

在 PCP + DCP 模式下，若请求过短不够分满 2P 个 Chunk（(2P - 1) * chunk_size >= L），自动在全卡完整复制，防止集合通信死锁。

PCP 核心机制 ③：GLM-5.3-Flash Prefill 异构层算子流与异步重叠

34 层 KDA 先 AllGather 还原因果顺序再 ReduceScatter；11 层 SFA+KPool 用 all_gather_async 重叠本地 Query 投影

GLM-5.3-Flash 动态算子流 · PCP Prefill / Chunked Prefill 双支路对比：Branch A (34层 KDA) vs Branch B (11层 NoPE SFA + KPool)

Branch A · 34 层 KDA：因果还原 → TP×PCP 状态推进 → ReduceScatter

入口 all_gather(hidden)[hidden_restore_idx] 恢复 [T_global] 推进 64/(TP×PCP) 个 Head 状态，出口按 padded_gather_idx 一步 ReduceScatter 切回 [T_pcp]！

Branch B · 11 层 SFA+KPool：异步 Key Gather 重叠 + 本地 1/PCP Query

prepare_pcp_hidden 异步 Gather Key Hidden（与本地 wq_b / q_b_proj 重叠）更新全局 KPool；SFA 仅对本卡 T_pcp 个 Query 计算稀疏注意力。

PCP 核心机制 ④：GLM-5.3-Flash Decode 状态同步与 TP × PCP 权重切分

利用 PCP 引入的额外 Rank 联合切分 Embedding / 34层 KDA 投影与状态 / 11层 SFA o_proj / LM Head 四大常驻显存

GLM-5.3-Flash 动态算子流 · PCP Decode 锁步状态推进与 TP × PCP 四大常驻权重切分流水线

1. 为什么 Decode 请求保持复制？

34 层 KDA 的 64 个 Head 状态分散在 TP×PCP 各卡上，保持相同的 Decode 请求顺序可让所有卡免通信锁步推进本地 SSM 状态。

2. KDA 权重与状态 1/(TP×PCP)

PCPGlm5NextMergedColumnParallelLinear 将 34 层 KDA 的投影权重、Conv1d 状态和 Recurrent 状态全按 TP×PCP 切分。

3. Embedding / o_proj / LM Head

默认开启词表 Embedding、LM Head 以及 SFA ParallelOProjection 的跨 PCP 权重切分，显著释放单卡 HBM 空间。

PCP + DCP 叠加原理：算力与显存的双重切分

在 TP × PCP 网格上复用进程组建 DCP（支持 DCP = PCP 或 DCP = TP × PCP）

PCP 切分计算，但只有 DCP 切分 KV Cache

• 逻辑 DCP 组按 flat_idx = tp_rank * PCP + pcp_rank 组建，dcp_local_rank = flat_idx % DCP。
• Prefill 阶段各 PCP Rank 虽然通过 AllGather 获得了完整序列的新 KV，但只有满足 (pos // I) % DCP == dcp_local_rank 的 Token 会写入本卡物理 Slot，其余位置均被掩码为 -1。

[示例：TP=2, PCP=2, DCP=4]

TP Groups  : [0, 1] (PCP0), [2, 3] (PCP1)
PCP Groups : [0, 2] (TP0),  [1, 3] (TP1)
Logical DCP: [0, 2, 1, 3] (PCP-first, then TP)
HCCL Sorted: [0, 1, 2, 3] (dcp_collective_rank_order)

Stacked Prefill：全局统一发送计划 + 掩码写入

• 当前步新 KV：通过 build_pcp_ordered_slot_mapping 将全局 Slot 按 padded_gather_idx 重排，并用 ~gathered_kv_write_mask 过滤 Padding 与重复行。
• 历史 Cached KV：不同 PCP Rank 的 Head/Tail 分片历史长度不同，因此由 _get_pcp_prefill_kv_inputs 基于 global_batch 生成统一的 DCP AllGather 发送上界，接收后各虚拟片段只消费各自对应的历史区间。

Stacked Decode：两级融合归并 dcp_a2a_fused(tp, pcp)

• Decode 请求在 PCP Rank 间复制，每张卡负责本地 1/DCP 的历史 KV 分片。
• 若 DCP == PCP：同组 Q Heads 已相同，无需跨 TP Gather Q，直接跨 PCP 归并 (O, LSE)。
• 若 DCP == TP × PCP：先在 tp_group 内 Gather Q Heads，算完局部 Attention 后调用 dcp_a2a_fused(..., tp_group, pcp_group) 一步完成跨 TP Head Scatter 与跨 PCP LSE 归并！

部署场景选型与未来演进规划

面向生产与超长上下文的典型配置范式，以及 vLLM-Ascend 序列并行的下一步优化方向

1. 典型部署选型范式（以 GLM-5.3-Flash 为例）

• PD 分离部署（950DT / A3 1M 上下文推荐拓扑）：
  – Prefill 节点：DP1 + TP1 + PCP8 + EP8（利用 PCP8 将长 Prompt 切为 16 个 DualChunk 并行计算，并将 KDA 64 Heads 与 Embedding/LM Head 切到 8 张卡，大幅压降 TTFT）。
  – Decode 节点：DP8 + TP1 + PCP1 + EP8（配合 FULL_DECODE_ONLY 图模式 + MTP5 + ReplaySSM 最大化吞吐）。
• 混部 / 超长序列（128K ~ 1M+）：
  – 开启 DCP（设置 --cp-kv-cache-interleave-size == block_size）消减 TP/PCP 间的 KV Cache 冗余，单机即可承载百万 Token 上下文。

2. 未来规划与持续演进方向（Roadmap）

• KPool / 混合线性层下的 PCP Decode Request Sharding：
  – 目前 model_uses_kpool_indexer 下 Decode 保持 Replicated 以同步推进各卡 Mamba/KDA 状态（见 common_cp.py TODO）；后续将支持跨 PCP Rank 的 Recurrent State 归属与 Sharded Decode。
• BlockTable 架构对齐上游 vLLM #57169：
  – 将 AscendBlockTables 收敛为 Manager-Block 粒度，把 Kernel-Block 展开映射下沉至 AttentionGroup。
• 算子融合与动态 CP（Dynamic CP）：
  – 拓展 dcp_q_replicate（TPA）与 dcp_a2a_fused A3/A5 动态 Tiling；探索按请求序列长度跨 DP 动态弹性组建 CP 通信组。

短/中序列 (4K ~ 32K)

优先标准 DP / TP；DCP 在短序列下通信收益小于开销，无需开启。

中长序列 (32K ~ 256K)

开启 PCP 显著降低首字时延 TTFT，吞吐优于纯 TP、时延优于纯 DP。

超长序列 (128K ~ 1M+)

开启 DCP 或 PCP + DCP，释放成倍 KV 容量并降低长序列 Decode TPOT。

    def _dcp_all_gather_fragments(self, *tensors: torch.Tensor, dim: int) -> tuple[torch.Tensor, ...]:

            return ()

        if dim == 1 and pcp_group is not None and pcp_group.world_size > 1:
            # Query heads are replicated across PCP ranks. Gather only
            # distinct TP heads when DCP spans the full TP x PCP domain.
            if self.dcp_size == pcp_group.world_size:
                return tensors
            gathered = self.tp_group.all_gather(torch.cat(tensors, dim=-1).contiguous(), dim=dim)
        else:
            gathered = self._dcp_all_gather(torch.cat(tensors, dim=-1), dim)
        return torch.split(gathered, split_sizes, dim=-1)

    def replicated_requests(
        self, num_scheduled_tokens: np.ndarray, is_prefilling: np.ndarray
    ) -> np.ndarray:
        """Per global request, whether every PCP rank gets the whole query."""
        num_chunks = 2 * self.pcp_world_size
        query_lens = np.asarray(num_scheduled_tokens, dtype=np.int64)
        replicated = ~np.asarray(is_prefilling, dtype=np.bool_)
        if self.dcp_world_size > 1:
            chunk_sizes = (query_lens + num_chunks - 1) // num_chunks
            drops_a_chunk = (num_chunks - 1) * chunk_sizes >= query_lens
            replicated |= drops_a_chunk
        return replicated

    def _iter_rank_chunks(self, rank: int, num_scheduled_tokens: np.ndarray, is_prefilling: np.ndarray):

        num_chunks = 2 * self.pcp_world_size
        replicated = self.replicated_requests(num_scheduled_tokens, is_prefilling)
        for global_batch_req_idx, num_tokens in enumerate(num_scheduled_tokens):
            query_len = int(num_tokens)
            if query_len == 0:
                continue
            if not replicated[global_batch_req_idx]:
                chunk_size = (query_len + num_chunks - 1) // num_chunks
                chunk_indices = (rank, num_chunks - 1 - rank)
            elif self.shard_decode_requests:
                chunk_size = query_len
                owner_rank = decode_ordinal % self.pcp_world_size
                decode_ordinal += 1
                chunk_indices = (0,) if rank == owner_rank else ()
            else:  # DCP requires decode queries on every participating rank.
                chunk_size = query_len
                chunk_indices = (0,)
