部署场景选型与未来演进规划

面向生产与超长上下文的典型配置范式，以及 vLLM-Ascend 序列并行的下一步优化方向

1. 典型部署选型范式（以 GLM-5.3-Flash 为例）

• PD 分离部署（950DT / A3 1M 上下文推荐拓扑）：
  – Prefill 节点：DP1 + TP1 + PCP8 + EP8（利用 PCP8 将长 Prompt 切为 16 个 DualChunk 并行计算，并将 KDA 64 Heads 与 Embedding/LM Head 切到 8 张卡，大幅压降 TTFT）。
  – Decode 节点：DP8 + TP1 + PCP1 + EP8（配合 FULL_DECODE_ONLY 图模式 + MTP5 + ReplaySSM 最大化吞吐）。
• 混部 / 超长序列（128K ~ 1M+）：
  – 开启 DCP（设置 --cp-kv-cache-interleave-size == block_size）消减 TP/PCP 间的 KV Cache 冗余，单机即可承载百万 Token 上下文。

2. 未来规划与持续演进方向（Roadmap）

• KPool / 混合线性层下的 PCP Decode Request Sharding：
  – 目前 model_uses_kpool_indexer 下 Decode 保持 Replicated 以同步推进各卡 Mamba/KDA 状态（见 common_cp.py TODO）；后续将支持跨 PCP Rank 的 Recurrent State 归属与 Sharded Decode。
• BlockTable 架构对齐上游 vLLM #57169：
  – 将 AscendBlockTables 收敛为 Manager-Block 粒度，把 Kernel-Block 展开映射下沉至 AttentionGroup。
• 算子融合与动态 CP（Dynamic CP）：
  – 拓展 dcp_q_replicate（TPA）与 dcp_a2a_fused A3/A5 动态 Tiling；探索按请求序列长度跨 DP 动态弹性组建 CP 通信组。

短/中序列 (4K ~ 32K)

优先标准 DP / TP；DCP 在短序列下通信收益小于开销，无需开启。

中长序列 (32K ~ 256K)

开启 PCP 显著降低首字时延 TTFT，吞吐优于纯 TP、时延优于纯 DP。

超长序列 (128K ~ 1M+)

开启 DCP 或 PCP + DCP，释放成倍 KV 容量并降低长序列 Decode TPOT。
