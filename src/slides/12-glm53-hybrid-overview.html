实战案例：GLM-5.3-Flash 混合架构与 CP 职责拆解

45 层主干（34 层线性 KDA + 11 层稀疏 NoPE SFA / KPool + mHC + MoE）在 PCP & DCP 下的异构协同

34 LAYERS · LINEAR ATTN

KDA 线性注意力层

Heads & SSM State 按 TP × PCP 联合切分（64 Heads / (TP×PCP)）。
PCP Prefill 时先 AllGather hidden_states 并按 hidden_restore_idx 还原因果顺序推进状态，输出经 ReduceScatter 切回本地。

11 LAYERS · KPOOL INDEXER

KPool 稀疏索引器

压缩 Pool Cache (4:1) + FP32 Tail Ring 全量复制。
PCP Prefill 调用 all_gather_async 收集 Key Hidden（与本地 wq_b Query 投影重叠！），还原全局顺序更新 Cache，仅对本地 Query 选 Top-2048。

11 LAYERS · SPARSE ATTN

NoPE SFA 主注意力

支持 PCP 输入切分 + DCP 主 KV Cache 序列分片（512 Latent Dim，RoPE=0）。
Decode 阶段将 Replicated Indexer 选出的全局 Top-K 索引重映射为本地 DCP KV 索引，计算后经 dcp_a2a_fused 归并。

45 LAYERS · mHC & MoE

mHC 流混合 & EP MoE

4 条残差流 hc_pre / hc_post 与 MoE 专家路由保持在 PCP 本地 Token 视图（[T_local, 4096]）上执行，与 EP All-to-All 及 Shared Expert 多流重叠无缝正交。

GLM-5.3-Flash 的 5 组异构 KV / State Cache 在 PCP & DCP 下的存储契约

Cache Group 对应模块与层数 单 Token 维度 / 精度 PCP 行为 (Prefill) DCP 行为 (Storage)
Group 0 · SFA Main KV 11 层 SFA (+ 1 层 MTP) Latent 512 (BF16 / INT8 / FP8) PCP Gather 后按 Owner 写入 DCP 交错切分 (1/DCP)
Group 0 · KPool Indexer 11 层 Indexer 压缩池 128 dim / 4 tokens (BF16/INT8/FP8) 异步 Gather Hidden 还原顺序写 全量复制 (Replicated)
Group 1 · KPool Tail Ring 11 层未满池尾部环 [2 (K/Gate), Ring, 128] (FP32) 随 Indexer 全局顺序推进 全量复制 (Replicated)
Group 2~4 · KDA State A/B/C 34 层 KDA (12+11+11 层) Conv (BF16) + Recurrent (BF16/FP32) Gather Hidden 还原因果顺序推进 按 TP × PCP 切分 Heads
